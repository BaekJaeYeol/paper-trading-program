# 모의 주문에 적용한 진입 필터

## 적용 범위

신규 배포 config.json의 `entry_strategy`를 `trend_guard`로 설정했다.
이는 기존 신호에 진입 제한을 추가하는 모의 실험이며 실제 시장 수익 우위가 검증됐다는 뜻이 아니다.
필터를 강화하면 매수 기회도 줄어들 수 있다. 실계좌 주문은 비활성화 상태다.
실제 브로커 주문/계좌 설정을 이번 개발 작업에서 실행하거나 변경하지 않았다.

## 기본 조건

기존 거래량 배수·21거래일 수익률 상한을 통과한 뒤 다음을 모두 확인한다.

- 완료된 이전 거래일까지 일봉 60개 이상
- 직전 종가 >= 20거래일 종가 평균 > 60거래일 종가 평균
- 21거래일 수익률 >= -10%

데이터 부족이나 필터 탈락 시 해당 종목의 호가 조회·신규 주문을 하지 않는다.
거래량/추세 조건은 직전 거래일까지만 계산하며 당일 미완성 일봉을 사용하지 않는다.
기존 갭·호가 나이·스프레드·비중·손실 한도·미확인 주문·계좌 동기화·STOP 검증은 유지한다.
일봉 조회 범위는 180일로 늘려 60거래일 워밍업을 확보하려 한다. 응답 자체가 부족하면 여전히 진입하지 않는다.

선택 가능한 `trend_volatility_guard`는 위 조건과 14일 평균 True Range/종가 <= 5%를 함께 적용한다.
기본값은 이 추가 변동성 필터가 없는 `trend_guard`다. 어떤 임계값도 시장에서 최적이라고 입증하지 않았다.

## 설정과 기존 사용자

GUI `설정`의 `미국 모의 진입 필터`에서 기존 거래량/추세·급락/추세·변동성 필터를 선택한다.
자동 실행 중에는 설정을 바꿀 수 없다. 중단 뒤 저장하고 다음 모의 실행의 새 대조를 거친다.
상단에 현재 진입 필터를 표시하고 시작 확인 창에도 이름과 수익 우위 미검증 상태를 표시한다.
로그에는 기본 신호 통과 후 필터 때문에 제외된 종목 수를 표시한다.

기존 PC의 config.json에 entry_strategy가 없으면 호환성을 위해 baseline으로 해석한다.
기존 사용자는 설정에서 추세·급락 제한을 선택해 저장해야 적용된다. 사용자 PC 파일을 원격 수정하지 않았다.
키를 넣지 않은 기존 설정을 몰래 변경하지 않는다. 알 수 없는 전략 값은 설정 오류로 거부한다.

전략 변경만으로 기존 주문을 취소/정정하거나 보유종목을 청산하지 않는다.
중복 주문 키 `sb-v1-종목-세션`은 그대로 유지하며 전략 변경으로 같은 날 재주문을 허용하지 않는다.
과거 주문의 손절·익절·수량은 기존 원문으로 계속 대조한다.

## 연구와 백테스트

추세/변동성 코드를 연구·백테스트·주문 엔진에서 공유한다.
일반 백테스트는 선택된 설정을 사용한다. 연구 비교의 baseline은 계속 기존 신호로 고정해 후보와 비교한다.
연구 보고서의 후보가 현재 설정을 자동으로 변경하지는 않는다.
65개 봉의 기존 합성 데모는 31번째 봉에서만 거래량 신호가 있어, 새 기본 필터로는 거래 0건이 정상이다.
실제 장기 일봉에서 기존 신호와 비교하는 성과 검증은 아직 필요하다.

## 검증

단위 테스트는 신규/구형 설정, 정상 추세, 횡보·급락·과도한 변동성·60봉 미만 차단,
조건 탈락 시 호가/POST 없음, 브래킷 유지, 전략 전환 후 중복/미확인 주문 차단, 연구 baseline과 백테스트 일관성을 확인한다.
기존 브로커 fixture를 60개의 상승 일봉으로 바꿔 필터를 통과한 뒤 주문 안전성을 검증하도록 유지했다.
Windows GUI CI는 횡보 거래량 급증을 제외하고 설정에서 기존 신호로 바꾸면 후보가 나오며,
다시 추세 필터로 복귀하는 실제 UI 흐름을 확인한다. 브로커는 오프라인이다.
실제 API·사용자 PC·시장 수익 개선은 미검증이다.
기존 설정/상태 문구에 선택 필터를 연결하는 설계이며 Figma 도구 한도로 증분은 본 문서로 명세한다.
