# 전체 계좌·주문 대조 시간 제한

## 문제와 변경

매 주문 실행 전 새 계좌·주문 대조는 이미 수행하고 있었다.
그러나 여러 주문 조회에 오래 걸려도 마지막 잔고 조회만 최신이면 통과할 수 있었다.
이제 첫 계좌 조회부터 주문·자식 주문·최종 잔고·이력 작성까지 전체 대조를 monotonic 60초 시간 제한으로 검사한다.

시간 제한은 조회 전후와 최종 DB 커밋 직전의 체크포인트에서 검사한다.
진행 중인 HTTP 호출이나 SQLite 작업을 강제 취소하지 않는다. 따라서 전체 함수가 정확히 60초 안에 반환한다는 보장은 아니다.
현재 호출이 반환한 뒤 초과를 발견하면 후속 조회/주문을 진행하지 않는다.

## 실패 동작

- 시간 초과는 고정 코드로 GUI에 전달하며 오류 원문을 노출하지 않는다.
- GUI 자동 실행·예약을 중단하고, 진행 중인 작업 완료 뒤 기존 절전 방지 요청을 해제한다.
- 화면에 `전체 대조 60초 시간 제한 초과`와 계좌·주문 재점검 및 명시적 재개 절차를 표시한다.
- CLI run은 시간 초과 뒤 재예약하지 않고 종료한다. 절전 방지 해제 finally는 그대로 수행한다.
- 실패·취소 시 이전 `inventory_gate.ready` 판정을 무효화한다. DB 접근 자체가 실패하면 저장을 보장할 수 없지만 호출 측 자동 실행은 중단한다.
- STOP을 임의로 제거/생성하거나 주문을 재전송·취소·청산하지 않는다.

성공 시 진단 집계에 `reconciliation.elapsed_seconds` 정수(올림)를 포함한다.
실패한 결과는 정상 스냅샷으로 표시하지 않으며, 이전 진단 캐시는 조회 실패·오래된 정보 표시를 유지한다.

## 트랜잭션

개별 주문의 확인 이력은 기존처럼 단계별로 저장할 수 있다.
최종 진입 게이트·선택 기록 복구 해소·복구 감사 이력은 하나의 최종 트랜잭션에 모은다.
최종 이력 구성 중 시간이 초과되어도 복구 해소나 진입 가능 판정을 커밋하지 않는다.
정상 대조를 다시 수행하면 게이트를 새로 검증할 수 있으나, 이것만으로 GUI가 자동 재개되지는 않는다.

## 검증과 한계

가상 시간 단위 테스트: 첫 조회 지연, 자식 주문 조회 지연, 후속 조회 방지, 기존 게이트 무효화,
최종 복구 트랜잭션 롤백, 성공 소요 시간, GUI 고정 오류 표시/중단/절전 해제, CLI 종료.
Windows GUI CI는 저널 전용 가상 시계를 65초 진행시켜 실제 시간 제한 코드와 자동 실행 중단·명시적 재시작을 확인한다.
실제 65초 대기, OS 절전·복귀, 하루 이상 연속 실행, 네트워크 장애 실기 검증을 대신하지 않는다.

조회할 주문 이력이 많거나 API가 느리면 안전하게 중단될 수 있다. 대규모 이력의 증분 대조는 별도 미구현이다.
여러 GET은 원자적 브로커 스냅샷이 아니며, 실제 계좌 안전성이나 다음 거래일 정시 실행을 보장하지 않는다.
실계좌 주문은 계속 비활성화 상태다.
기존 상태 문구를 보강하는 설계이며 Figma 도구 한도로 증분 상태는 본 문서에 명세한다.
