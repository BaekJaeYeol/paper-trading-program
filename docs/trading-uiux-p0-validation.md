# 거래 UI/UX P0 1차 구현 및 검증

Figma: https://www.figma.com/design/y2jpjfK5bq7FxDDd4131lK
설계 프레임: 계좌·주문 상태(2:11), 비상 중단 결과(2:40), 재개 전 점검(2:51).

## 구현한 범위

- 상단 모의투자·브로커·시장·통화·실계좌 비활성화 표시. 계좌 별칭은 일반 이름이며 실제 계좌 식별자를 표시하지 않는다.
- 마지막 정상 **계좌 응답 수신 시각**(KST)과 경과 시간. 60초 이상은 오래된 계좌 정보, 조회 실패 시 이전 데이터로 표시한다. 60초는 운영 표시 기준이며 시세 유효성을 보장하지 않는다. 시세 기준 시각은 기존 엔진에서 별도 검사한다.
- 주문 수량·체결·잔여 수량 및 접수·부분 체결·취소 요청/완료 구분. 브로커 상태 미인식은 미확인으로 표시한다. 미체결만 조회하며 전체 주문 타임라인은 아직 구현하지 않았다.
- STOP 파일 존재 확인 후 차단 확인 표시. 파일 쓰기 실패는 중단 기록 실패로 표시한다. GUI 실행에는 메모리 중단 이벤트도 전달한다. 이미 전송된 주문, 다른 PC/프로세스, 기존 주문 취소·보유 청산은 보장하지 않는다.
- 늦게 도착한 계좌/후보/주문 응답이 STOP 상태를 덮어쓰지 않는다.
- 재개 전 cycle 잠금, 계좌 거래 가능 상태, 잔고·미체결 조회 및 미확인 로컬 주문을 검사한다. 60초 초과 조회는 재개를 차단한다. 점검 중 중단하면 재개하지 않는다.
- 로컬 pending/unknown 주문이 남으면 다른 종목을 포함해 신규 제출을 차단한다. 미확인 주문을 재전송하거나 임의로 삭제하지 않는다. 증권사에서 대조한 후 별도 복구 작업이 필요하다.

## 검증

Python 3.12/Linux에서 기존 26개 + 추가 9개, 총 35개 테스트 통과. 소스 컴파일 성공. 테스트는 가짜 브로커/임시 SQLite를 사용하며 실제 인증·주문을 실행하지 않는다.

Figma 대시보드의 편집 가능한 계층, 변수 및 대체 한글 글꼴(Noto Sans KR)을 확인했다. Windows 구현은 기존 맑은 고딕을 유지한다. 설계상 숫자·계좌는 예시이며 실제 수익이 아니다.

Windows GUI 워크플로를 PR에도 실행하도록 변경했다. 기존 Windows 마우스/키보드 검사에 부분 체결 잔여 수량과 중단 중 늦은 응답 사례를 추가했다. 새 커밋의 Windows 실행 결과는 PR의 체크 결과를 확인해야 하며 스크립트 추가만으로 통과를 주장하지 않는다. 로컬 가상 디스플레이 도구가 없어 이번 환경의 실제 Tk 렌더링 검증은 미수행이다.

## 남은 P0 및 적용 한계

- 재개 점검은 브로커 스냅샷 조회와 미확인 주문 차단이다. 기대 보유량과 실제 잔고의 완전 대조, 계좌 간 상태 디렉터리 바인딩, 모든 주문의 체결 추적 및 자동 복구는 미구현이다.
- 기존 recovery.Coordinator는 아직 legacy cycle/GUI에 연결하지 않았다.
- 실제 KIS/Alpaca 인증, 모든 장애의 실제 서버 재현, Windows 11 사용자 환경, 스크린리더·고배율·전체 WCAG 준수 및 실제 사용자 평가는 미검증이다.
- 한국은 잔고 조회 전용이다. 토스/실계좌 주문을 활성화하지 않았다.
