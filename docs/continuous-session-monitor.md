# 24시간 세션 감시와 시간외 주문 제한

## 요청과 실제 적용 범위

요청은 시간외 거래까지 포함한 상시 운영이다.
이번 변경은 정상 연결 상태에서 계속 실행하며 정규장 밖을 감시하고, 정규장으로 복귀하면 새 대조 뒤 기존 모의 주문을 수행하는 부분이다.
**프리마켓·애프터마켓·야간의 신규 주문 실행은 미구현/미활성이다. 시간외 거래까지 완료했다고 해석하면 안 된다.**

현재 Alpaca 주문 안내의 브래킷 제약은 시간외 지원 불가이고 extended_hours는 false 또는 생략이어야 한다.
손절·익절을 제거한 단순 지정가로 몰래 바꾸지 않는다. 기존 주문 원문과 보호·중복 방지 요구를 유지한다.
공식 근거: https://docs.alpaca.markets/us/docs/orders-at-alpaca

## 운영

기존 `모의매매 시작` 또는 CLI `run --execute-paper`로 감시를 시작한다.
- 정규장: 기존 300초 기준 주기(GUI), CLI는 --interval 유지
- 정규장 외: 60초 기준 세션/계좌·주문 점검, 신규 주문 없음
- 정규장 복귀: 계좌·주문 대조와 기존 위험 검증을 다시 거쳐 정상 주기로 복귀
- 지연된 예약은 건너뛰고 작업 완료 후 최소 30초 휴지 시간 유지
- STOP/사용자 중단은 감시까지 중단하며 재개는 기존 명시적 점검을 다시 거친다.

앱이 정상 동작 중인 동안의 전환이다. 네트워크/계좌/주문 불일치·대조 시간 초과 등 기존 장애 시 중단 정책을 유지한다.
PC 종료/수동 절전/프로세스 종료에서 자동 재기동하지 않으며 실제 하루 이상 연속 실행은 미검증이다.
Windows 유휴 절전 방지 요청은 자동 운영 중 유지하지만 정전·수동 절전 등은 막지 못한다.

## 세션 판정과 표시

브로커 clock과 전후 14일 calendar를 사용하고 미국 뉴욕 시간대로 해석한다.
정규장 실행에는 clock.is_open=true와 달력의 open/close 구간 일치가 모두 필요하다.
프리/애프터는 정상 거래일의 알려진 시간대를 진단용으로 구분한다. 조기폐장 뒤 시간외 구간은 추정하지 않고 미검증 대기한다.
야간은 다음 거래일 달력을 참고한 가능 시간만 표시하며 계좌/종목/시세 권한과 실제 거래 가능을 확인한 것은 아니다.
주말과 휴장일은 거래하지 않고 다음 정규장을 기다린다. KST 예정 시각은 ZoneInfo로 변환해 서머타임을 반영한다.
향후 야간/거래소 시간 개편을 자동 승인하지 않는다.

상단 상태에 현재 세션/신규 주문 대기를, `운영 상태 → 세션 상세` 읽기 전용 창에 다음 정규장 KST 시각과 시간외 미활성 상태를 표시한다.
시작 확인 창에도 시간외 신규 주문 차단을 명시한다.
호가 조회 후와 실제 POST 직전에 시장 시계·세션 날짜·호가 나이·STOP을 다시 확인한다.
직전 확인 뒤 네트워크 송신 중 장이 바뀌는 경쟁 상황까지 원자적으로 막는 기능은 아니다. 주문 응답은 기존 영속 저널로 추적한다.
시세 페이지 조회에는 10페이지/5000봉/60초 체크포인트 한도를 두고 반복 토큰을 차단해 잘못된 응답에 무한 대기하지 않는다.

## 시간외 실행에 추가로 필요한 것 (미구현)

- 계좌/상품별 시간외 및 overnight 권한·실시간 시세 출처 검증. 현재 IEX만으로 야간 가능을 가정하지 않음
- 지정가 진입/청산 전용 상태 머신, 부분 체결/취소 대기/통신 응답 미확인 추적
- 별도 포지션 원장과 기존 브래킷 원장의 충돌 방지, 세션 거래일/주문 유효기간 전환
- 시간외 손절·익절 대체 정책. 프로그램 감시형 청산은 앱/PC/네트워크 중단 시 서버 브래킷과 같은 보호를 보장하지 못함
- 정전·프로세스 종료·무호가·거래정지·갭·스프레드·불완전 체결 시나리오 검증

시간외 단순 지정가를 안전성이 검증된 브래킷 주문과 동일하다고 취급하지 않는다.
유료 시세 신청·계좌 권한 변경·실계좌 주문 활성화는 이번 작업에서 하지 않았다.

## 검증

가상 시계 테스트로 정규/프리/애프터/야간 가능/주말/휴일/조기폐장/서머타임/시계 불일치를 확인한다.
정규장 밖 주문·호가·매매 데이터 조회가 없고, 장 마감 또는 호가 노후화가 POST 직전 발견되면 주문하지 않음을 검증한다.
Windows GUI CI는 애프터마켓 감시 전환(60초)과 정규장 복귀(300초), 주문 수 불변을 오프라인으로 검증한다.
실제 24시간 운전·시간외 API 체결·야간 계좌 권한·사용자 PC 환경은 미검증이다.
기존 운영 상태/시작 안내를 확장하는 설계이며 Figma 도구 한도로 증분 상태는 본 문서로 명세한다.

추가 공식 근거: https://docs.alpaca.markets/us/docs/245-trading
