# 자동 실행 주기와 지연 처리

## 변경 목적

이전 GUI와 CLI run은 작업 완료 뒤 300초를 기다려, 처리 시간이 매번 실행 간격에 추가됐다.
이제 monotonic 시간의 시작 시각을 기준으로 다음 예약을 계산한다.
예: 0초에 시작해 40초에 완료하면 260초를 기다려 300초에 다시 시작한다.
GUI 기본 주기는 300초이며 CLI `--interval`은 기존처럼 최소 30초다.
첫 실행은 기존 계좌·주문 재개 점검을 통과한 직후 시작한다.

## 지연과 중단

- 늦어진 콜백은 현재 슬롯 하나만 처리한다. 지나간 슬롯을 반복 실행하지 않는다.
- 작업 중에는 두 번째 실행을 시작하지 않는다.
- 작업 완료 후 다음 시작까지 최소 30초(주기가 더 짧으면 그 주기)를 확보한다. 너무 가까운 슬롯은 건너뛴다.
- 예: 0초 작업이 950초까지 걸리면 300/600/900초 예약을 건너뛰고 1200초에 실행한다.
- 비상 중단은 예약 타이머를 취소한다. 뒤늦게 도착한 콜백도 실행 상태를 확인한다.
- 재개는 새 cadence를 생성하므로 이전 실행의 밀린 예약을 이어받지 않는다.
- 매 실행의 기존 계좌·주문 대조, STOP·시세·중복 주문·손실 한도 검증은 유지한다.

## 표시

대시보드 상단에 처리 중/다음 실행 예상 KST 시각/남은 초/지연으로 건너뛴 슬롯 수를 표시한다.
다음 시각은 monotonic 남은 시간을 현재 시계에 더한 예상치다. PC 시계 변경은 표시 시각에 반영되지만 예약 간격 계산은 벽시계를 사용하지 않는다.
CLI run은 대기 초와 누적 건너뛴 슬롯 수를 로그로 출력한다.

## 한계와 검증

실시간 스케줄러나 거래소 세션 예약 기능이 아니다. PC 절전·종료·인터넷 단절·운영체제 부하·장시간 API 호출로 인한 지연 자체를 방지하지 못한다.
절전에서 깨어난 뒤에도 밀린 작업을 일괄 실행하지 않으며, 주문 전 기존 검증을 다시 수행한다.
운영체제별 suspend 동안의 monotonic 경과 동작과 다음 거래일 첫 예약의 정시 실행은 별도 실기 검증 대상이다.
일별 전략/거래소 시간표와 실계좌 활성화 범위는 변경하지 않는다.

단위 테스트는 가상 시간으로 주기 계산, 지연/중복 콜백, 작업 중 겹침, 최소 휴지 시간, GUI STOP과 CLI 실제 반복 경로를 확인한다.
Windows GUI CI는 다음 실행 표시와 지연 콜백 fixture를 확인한다. 실제 5분 대기·절전·하루 이상 연속 실행을 대신하지 않는다.
Figma Starter 도구 한도로 이번 상단 상태 표시 증분은 문서로 명세하며 Figma 추가 반영은 하지 못했다.
