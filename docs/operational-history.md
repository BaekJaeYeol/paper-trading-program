# 재시작 후 미국 모의계좌 대조 운영 이력

## 화면

`운영 상태` 탭은 저장된 미국 Alpaca 모의계좌 대조 이력을 표시한다.
행을 선택하고 Enter/더블클릭하면 최초·마지막 확인 시각(KST), 반복 횟수, 다음 확인 절차를 볼 수 있다.
`운영 이력 새로고침`은 로컬 DB만 읽으며 브로커에 요청하지 않는다.
앱 재시작 시에도 이력을 읽지만 계좌를 자동 연결하거나 자동매매를 시작하지 않는다.
과거 복구 기록은 현재 계좌 상태나 자동매매 재개 승인이 아니다.

상태는 시간 초과, 사용자 취소, 대조 실패, 대조 완료이나 진입 차단, 대조 복구로 구분한다.
정상 조회가 끝나도 미확인 주문/수량/검토 차단이 남아 있으면 `진입 차단`이다.
첫 정상 조회에는 가상의 장애·복구 기록을 만들지 않는다.
이력이 없을 때는 정상 연결을 뜻하지 않는다고 표시한다. DB 조회 실패는 별도 안내하고 이전 표를 보존한다.

## 데이터와 개인정보

`orders.sqlite`의 `paper_system_events`에 고정 코드·최초/마지막 시각·반복 횟수만 저장한다.
API 키·계좌/주문 식별자·종목·금액·원시 응답·오류 원문·사용자 자유 입력 메모를 저장하지 않는다.
같은 코드가 연속되면 한 묶음의 횟수/마지막 시각만 갱신한다.
최근 200개 상태 묶음을 보존하고 화면에는 최근 최대 50개를 표시한다.
진단 JSON은 고정된 최근 코드와 표시된 묶음별 코드 건수만 포함한다. 전체 운영 횟수나 감사 로그가 아니다.

이력은 해당 상태 폴더의 미국 모의 대조에 한정한다. KIS, 모든 GUI 오류, POST 오류 전체 또는 OS 장애를 포괄하는 로그가 아니다.
프로세스가 강제 종료되거나 DB를 쓸 수 없으면 마지막 사건 저장을 보장하지 못한다.
대조 잠금을 획득하지 못한 다른 프로세스는 이력 DB를 수정하지 않는다.

## 원자성과 복구

실패 이벤트는 기존 진입 게이트 무효화와 함께 저장한다.
복구/차단 이벤트는 최종 대조·복구 기록 트랜잭션과 함께 저장하므로 최종 실패 때 거짓 복구 기록을 남기지 않는다.
운영 이력은 읽기 전용이며 열기/닫기/새로고침으로 STOP·주문·차단을 변경하지 않는다.
실계좌 주문은 계속 비활성화 상태다.

## 검증

단위 테스트: 상태 구분/중복 집계, 최초 정상 상태, 보존·표시 한도, 잘못된 코드/시각 비노출,
읽기 전용/손상·잠금 DB, 롤백, 연결 재생성 후 이력 복원, 시간 초과/취소/실패/복구와 상세 창 비변경.
Windows GUI CI: 실제 탭/키보드 상세 창, 앱 종료 후 재실행, 시간 초과와 복구 기록 복원,
시작 시 브로커 GET/POST 0회·자동 실행 없음·STOP 유지 확인.
실제 증권사와 사용자 PC 장시간 운영/강제 종료 실험은 미검증이다.

기존 Notebook에 운영 상태 탭, 로컬 새로고침 버튼, 읽기 전용 상세 창을 추가하는 설계다.
Figma 도구 한도로 증분 화면은 문서로 명세했으며 Figma 추가 반영은 하지 못했다.
