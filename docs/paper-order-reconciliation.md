# 미국 모의계좌 주문 대조 및 재시작 복구

## 화면 흐름

Figma P0 추가 설계: https://www.figma.com/design/y2jpjfK5bq7FxDDd4131lK?node-id=5-5

기존 `계좌 새로고침`은 **계좌·주문 대조**로 바뀝니다. 계좌·잔고·미체결을 읽고, 이 봇이 저장한 주문 키로 주문을 조회한 뒤 결과를 `봇 주문 추적`과 `주문 변경 기록` 탭에 표시합니다. 네트워크는 작업 스레드에서 처리하며 대조 중 추가 작업은 잠급니다. 중단 버튼은 유지됩니다.

- 조회 성공: 원래 요청의 종목·방향·수량·지정가·유형·기간·주문 종류 및 브로커 주문 ID와 누적 체결을 대조합니다.
- 접수·부분 체결·취소 요청 중·취소 완료·체결 완료를 구분합니다.
- 동일 상태의 반복 조회는 변경 이벤트를 중복 저장하지 않습니다.
- 응답 유실로 unknown이 된 주문을 찾으면 확인한 브로커 상태로 갱신합니다. 주문을 다시 제출하지 않습니다.
- 404 조회 없음, 통신 오류, 주문 정보 불일치, 누적 체결 감소는 재개를 계속 차단합니다. 조회 없음은 미접수의 증거로 사용하지 않습니다.
- 대조 전후 계좌 응답의 지문을 확인합니다. 상태 폴더는 처음 확인한 Alpaca 모의계좌의 해시 지문에 묶이며 다른 계좌에 재사용하면 차단합니다. 실제 계좌 ID와 키를 화면/로그에 저장하지 않습니다.
- 대조는 STOP을 생성하거나 지우지 않으며 자동매매를 자동으로 재개하지 않습니다. 재개는 기존 시작 버튼의 점검·확인 절차를 거칩니다.
- 대조 도중 중단하면 진행을 중단하고 재개하지 않습니다. 이미 진행 중인 조회는 기존 HTTP 제한시간 이후 종료될 수 있습니다.

## 영속 기록

기존 `orders.sqlite`의 2열 attempts 테이블을 그대로 유지하고 paper_requests, paper_checks, paper_events, paper_meta를 추가합니다. 원래 주문 원문과 pending 의도를 **같은 트랜잭션으로 POST 전에 커밋**합니다. 주문 응답이 불확실하면 원문과 unknown을 남깁니다. 영속 주문 키는 확인/취소/체결 후에도 재사용하지 않습니다.

이전 버전의 주문은 원문이 없으므로 안전한 자동 대조 대상이 아닙니다. 이전 pending/unknown은 계속 재개를 차단하고 수동 확인을 안내합니다. 이전 submitted 기록은 과거 형식으로 표시하며, 완전한 상태 추적이 된 것처럼 표시하지 않습니다. 오류 해결을 위해 DB나 주문 기록을 삭제하지 마세요.

## 명령줄

프로젝트 폴더에서 `stockbot reconcile --config config.json`을 실행할 수 있습니다. Python 모듈 실행은 `python -m stockbot.cli reconcile --config config.json`입니다. API 키는 기존 로컬 환경변수만 사용합니다. 이 명령은 GET 조회와 로컬 기록 갱신만 수행하며 `--execute-paper`를 거부합니다. API 키를 채팅이나 GitHub에 올리지 마세요.

## 검증 및 한계

Python 3.12/Linux 로컬 테스트 55개 통과. 새 테스트는 가짜 브로커·임시 SQLite를 사용합니다. 응답 유실 후 재시작/부분 체결 발견, 404, 조회 타임아웃, 계좌 교체, 정보 불일치, 누적 체결 감소, 취소 요청/완료, 최종 체결, 반복 이벤트 중복 방지, 이전 DB 보존, 중단 및 GET 요청만 사용 여부를 확인합니다. Ctrl+Tab으로 주문 추적·변경 기록 탭을 이동할 수 있습니다. Windows GUI 검사에는 해당 키보드 이동과 미확인 주문 조회 실패 → 발견 → 부분 체결 표시와 STOP/제출 횟수 불변을 추가했습니다. Windows 실행 결과는 해당 PR의 최신 체크에서 확인하며 스크립트 추가를 성공으로 간주하지 않습니다.

- 이번 범위는 **이 봇의 진입 주문**입니다. 브래킷의 모든 자식 손절/익절 주문과 체결 취소·정정은 완전 추적하지 않습니다. 명시적 원문과 다른 주문은 자동 승인하지 않습니다.
- 계좌 잔고는 브로커 스냅샷이 기준입니다. 체결 누적으로 잔고를 재구성하거나 기대 보유량과 완전 대조하는 기능은 아직 구현하지 않았습니다.
- 최근 200개의 주문/변경 이벤트를 화면에 표시합니다. 기록 자체는 삭제하지 않습니다. 비종료 주문 조회는 기록 수에 비례하여 오래 걸릴 수 있습니다.
- REST 조회 사이에도 주문은 변할 수 있습니다. 실시간 스트리밍이나 원자적인 계좌·주문 스냅샷을 보장하지 않습니다. HTTP 요청의 실제 서버 동작과 Windows 11 사용자 PC, 보조기술 접근성은 별도 검증 대상입니다.
- 한국 KIS는 잔고 조회 전용이며 토스·실계좌 주문을 활성화하지 않습니다. 기존 recovery.Coordinator를 연결했다는 뜻이 아니며 실제 사용 중인 legacy cycle에 필요한 저널과 조회 복구를 연결한 구현입니다.
