# 브래킷 자식 주문과 관리 종목 보유 수량 대조

## 설계·화면

기존 P0 Figma 설계 https://www.figma.com/design/y2jpjfK5bq7FxDDd4131lK 를 유지하며 `보유 수량 대조` 탭을 추가합니다. 열은 종목/봇 기대 수량/계좌 실제 수량/대조 결과입니다. 일치와 불일치를 글자로 표시하며 불일치는 재개 차단 사유로 표시합니다. `봇 주문 추적`과 `주문 변경 기록`에는 익절·손절 자식 주문을 구분해 표시합니다.

추가 Figma 프레임 작성은 Starter MCP 호출 한도에 의해 차단되어 미완료입니다. 기존 프레임을 만들었다는 의미가 아니며 유료 업그레이드/결제는 하지 않았습니다. 추가 구조와 상태 규칙은 본 문서로 인계합니다.

## 처리 범위

- client_order_id로 부모를 찾고 주문 ID GET에 nested=true를 지정해 익절(limit)·손절(stop) 두 자식 주문을 조회합니다.
- 부모가 체결 완료여도 자식 주문은 이후 체결될 수 있으므로 대조 시 부모를 다시 조회합니다.
- 자식 ID·연결·종목·매도 방향·원래 가격·기간·누적 체결을 확인합니다. 익절 일부 체결에 따른 손절 수량 조정은 부모 수량 범위에서 허용합니다.
- 두 출구의 누적 체결 합계가 부모 누적 체결을 넘으면 차단합니다. 수량을 합산해 임의 매도하거나 역방향 주문하지 않습니다.
- 부모 전량 체결 후 자식 누락, 이미 저장한 자식의 소실/ID 변경/체결 감소, 정정·교체·가격 변경·지원하지 않는 그래프는 미확인으로 남깁니다. 자동으로 정상이라고 간주하지 않습니다.
- 검증된 봇 진입 체결에서 검증된 두 출구 체결을 빼서 **기록에 있는 관리 종목**의 기대 수량을 계산하고 브로커의 실제 보유 수량과 비교합니다. 동일 종목의 외부 수동 매매·주식분할 등도 불일치가 될 수 있으며 자동 보정하지 않습니다.
- 다른 종목의 수동 보유분은 관리 소유권에 포함하지 않으며 매도하지 않습니다. 계좌 전체 현금·세금·수익의 완전 회계 대조는 아닙니다.
- 원문 없는 과거 주문이 있으면 기대 수량을 검증할 수 없으므로 재개를 차단합니다. DB를 지워 문제를 숨기지 말고 증권사 기록과 수동 대조/이관이 필요합니다.

## 주문 경계

GUI 자동 주기와 CLI paper/run은 주문 전에 읽기 대조를 수행합니다. 미확인 주문 또는 수량 불일치가 있으면 GUI 실행을 멈추고 CLI 자동 실행도 재시작 안내로 종료합니다. 실제 제출 경계에서도 저장된 대조 차단 상태와 방금 조회한 보유량을 재확인합니다. 내부 cycle API를 직접 호출하는 기존 통합은 별도 대조 호출이 필요하며 전체 거래의 원자성을 보장하지 않습니다.

대조는 STOP을 지우거나 취소/청산/재전송하지 않습니다. REST 조회 사이에 체결이 바뀔 수 있으므로 일시적 스냅샷 지연도 안전하게 차단될 수 있습니다. 다른 프로세스/PC의 외부 주문, 실시간 스트리밍, 모든 정정·기업행위 처리는 별도 범위입니다.

## 검증

Python 3.12/Linux 로컬 68개 테스트 통과 및 소스 컴파일. 가짜 브로커와 임시 DB 사용. 전량 진입/부분 익절/손절 잔량 조정/출구 체결/자식 ID 변경/자식 누락/초과 체결/보유 불일치/무관한 수동 보유/STOP 보존을 검증합니다. 실제 인증·주문은 실행하지 않았습니다. Windows UI 검사는 일치·불일치 표시와 재개 차단을 추가했으며 결과는 최신 PR 체크에서 별도로 확인합니다. Windows 11 사용자 PC/실제 서버 장애/전체 접근성은 미검증입니다. 실계좌 주문은 비활성화 상태입니다.

공식 API 확인(2026-10-24):

- https://docs.alpaca.markets/us/docs/orders-at-alpaca — 브래킷 및 익절 부분 체결에 따른 손절 수량 조정.
