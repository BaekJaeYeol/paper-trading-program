# 주문 변화 검토와 차단 상세

모의 Alpaca 계좌 전용이다. 실계좌 주문은 활성화하지 않는다.

## 화면 및 동작

`계좌·주문 대조` 후 `차단 상세` 탭에서 대상을 선택하고 Enter 또는 더블클릭한다.
저장값/조회값, 최초·마지막 확인 시각(KST), 변경 기록 횟수와 다음 확인 절차를 표시한다.
확인 창은 읽기 전용이며 닫기 동작은 승인이나 재개가 아니다.

- 주문 정정·교체 링크/상태, 원래 수량·가격·조건 변경, 주문 ID 변경, 누적 체결 감소/종료 상태 변경: SQLite에 수동 검토 필요 기록을 유지한다. 이후 정상 조회에도 자동 해제하지 않는다.
- 조회 실패/조회 결과 없음: 정상 대조가 완료되면 일시적 사건을 해소 이력으로 남긴다. 해소되어도 자동매매를 자동 재개하지 않는다.
- 보유 수량 불일치: 원인 미확정으로 표시한다. 잔고와 주문 수량이 다시 일치하면 일시적 불일치 기록이 해소될 수 있다.
- 활성 사건이 하나라도 있으면 신규 진입과 재개를 차단한다. 중복 동일 관측은 변경 횟수를 증가시키지 않는다.

주식분할·합병·이체·수동 매매·체결 정정 등을 수량 차이만으로 확정하지 않는다.
공식 기업행위 피드 연동, 정정 주문 체인 자동 추적, 자동 수량 보정, 체결 정정 회계 처리는 미구현이다.
가격·주문 조건 사건에 한해 종료·무보유·원래 조건 복원 검증 뒤 선택 기록을 해소하는 GUI 절차가 있다. 자세한 제한은 [검증 후 복구](review-recovery.md)를 참조한다. 정정·교체·ID·수량·체결 변경은 해제하지 않는다.
DB/STOP 삭제를 복구 방법으로 사용하지 않는다. 기존 주문 취소·청산·재전송은 하지 않는다.

## 설계 및 검증 범위

기존 Tkinter Notebook에 차단 상세 목록과 키보드 접근 가능한 읽기 전용 창을 추가했다.
기존 Figma 설계 이후 추가된 화면 상태는 이 문서로 기록했다. Figma Starter 도구 한도로 이번 추가 설계는 Figma에 반영하지 못했다.

단위 테스트는 고정된 오프라인 주문 응답으로 차단 유지·일시 오류 해소·증거 표시·재시작 영속성·상세 창의 비변경 동작을 확인한다.
Windows GUI CI는 실제 Tk 창에서 교체 감지, 상세 창 키보드 열기/닫기, 정상 응답 후 차단 유지와 재개 거부를 확인한다.
실제 증권사 API, 기업행위 처리 및 사용자 PC에서의 실행 검증을 대신하지 않는다.
