# Windows 자동 실행 중 유휴 절전 방지

## 동작과 화면

Windows GUI는 계좌·주문 재개 점검과 확인 후 자동매매 시작 직전에 유휴 절전 방지를 요청한다.
요청 실패 시 STOP을 해제하거나 주문을 시작하지 않는다. 기존 STOP이 없더라도 신규 실행은 차단한다.
일반 계좌 조회·백테스트·대기 상태는 요청하지 않는다.

상단 예약 상태에 `절전 방지 요청 적용/해제/실패`를 표시한다.
중단 시 작업이 끝났으면 바로 해제하고, 진행 중인 통신 작업이 있으면 완료/실패를 처리한 뒤 해제한다.
실패 시 요청이 해제됐다고 표시하지 않는다. 중단/종료 시 다시 해제를 시도한다.
사용자의 PC 전원 계획이나 화면 꺼짐 설정을 영구 변경하지 않는다.

CLI `run --execute-paper`도 같은 요청을 사용하며 종료·Ctrl+C·예외 시 finally에서 해제한다.
대기 중에는 최대 5초 간격으로 STOP을 확인하고, STOP이 있으면 반복 실행을 종료한다.
실행 시작 때 STOP이 이미 있으면 절전 방지 요청과 브로커 조회 전에 종료한다.
진행 중 API 호출은 강제 취소하지 않으며 기존 요청 기록/중복 주문 방지는 유지한다.
Windows 이외 플랫폼은 지원하지 않음을 표시하며 기존 실행 동작을 유지한다.

## 구현 근거

Microsoft 공식 `SetThreadExecutionState` API:
https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate

- `ES_CONTINUOUS | ES_SYSTEM_REQUIRED` 요청으로 유휴 절전 타이머에 요구를 등록한다.
- 반환값 0을 실패로 처리한다.
- 같은 스레드에서 요청·해제하며, 요청 전 실행 플래그를 보존했다가 복원한다.
- 화면 유지·away mode는 요청하지 않는다. 화면이나 화면 보호기는 꺼질 수 있다.

API는 사용자의 수동 절전, 노트북 덮개 닫기, 전원 버튼, 종료를 막지 못한다.
관리자 정책·장치 동작·전원 부족을 극복하거나 네트워크/서버 가용성을 보장하지 않는다.
다음 거래일 첫 실행 정시성과 장시간 무중단 운영을 보장하는 기능이 아니다.

## 진단 및 검증

진단 JSON은 `sleep_prevention` 아래 지원 여부·요청 유지 여부·고정된 실패 코드만 추가한다.
로컬 단위 테스트는 실패/복원/스레드 소유권/중단 작업 대기/CLI 종료/외부 STOP 감지를 검증한다.
Windows 단위 테스트는 실제 API를 호출해 해당 테스트 스레드의 요청 비트와 이전 상태 복원을 확인한다.
Windows GUI CI는 실제 요청 적용/중단 해제/재개와 실패 주입 시 시작 차단을 확인한다.
오프라인 브로커를 사용하며 실제 PC를 절전시키거나 장시간 방치하는 검증은 하지 않는다.
실계좌 주문은 계속 비활성화 상태다.

기존 상단 예약 상태 문구에 요청 상태를 이어 표시하는 설계다.
