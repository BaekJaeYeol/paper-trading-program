# 장중 실행 기록의 빈 구간 검사

정규장 각 15분봉 종료 7분 뒤를 목표로, 2분 안에 시작한 운영 기록이 있는지 확인합니다. 아직 목표+2분이 지나지 않은 회차는 미판정입니다. 거래소 달력의 휴장일·조기 폐장·서머타임을 반영하며 개장 전과 주말에는 직전 거래일을 보여줍니다.

최근 200회 이력만 검사하므로 기록이 없는 회차가 곧 미실행의 확정 증거는 아닙니다. 늦은 시작·저장 누락·이력 보존 범위를 함께 확인해야 합니다. 기록 존재와 종목별 성공·실제 체결은 별도입니다. 이 기능은 지연을 표시하며 GitHub 예약 지연을 예방하지 않습니다. 세션 자체가 시작되지 않으면 새 경고도 갱신되지 않으므로 보고서 시각과 Actions 실행 기록을 함께 확인합니다.

## 2026-10-15 미국 정규장 관찰

한국시간 10월16일 00:35 첫 실행, 00:37부터 05:22까지 정렬된 15분 주기로 실행했습니다. 총21회, 모든 회차10종목 오류 없음. 정규장 개장(10월15일22:30)부터 첫 기록까지 약125분 공백입니다. 완료 봉 확인 목표26회 중19회 기록, 초기7회 기록 없음. 실행 중 주기와 최초 기동 지연을 구분해야 합니다.

GitHub Actions를 유일한 예약 기동기로 사용하는 한 정시 기동을 보장할 수 없습니다. 장 시작부터 끊김 없는 운영이 필수라면 상시 실행 환경 또는 Windows 작업 스케줄러 등 외부 기동기가 필요합니다. 기존 계좌를 초기화하거나 과거 모의 체결을 만들어 이 공백을 숨기지 않습니다.

## 2026-10-16 미국 정규장 관찰

한국시간 10월17일 00:22부터05:22까지 정렬된21회 운영 기록의 간격은899.755~900.240초였고 모든 회차10종목이 정상입니다. 마지막 완료 봉(미국16일19:45 UTC 시작,20:00 종료)까지 처리했고,470개 v1 전략 DB는 새 실행기에서도 복원 없이 이어졌습니다. 배포 검증과 반복 세션 모두 성공 종료했습니다.

완료 봉 확인 목표26회 중20회 기록, 초반6회는 기록이 없습니다.05:22의 추가 마감 후 점검은26개 목표에 포함되지 않습니다. 초기 지연이 해결됐다는 의미는 아닙니다.

## 한 실행 안에서 두 세션 직렬 인계

예약·배포는 먼저 기존 단위·저장·1회 수집 검사를 수행합니다. 성공하면 같은 워크플로의 두 `continue-session` 행렬 작업이 `max-parallel: 1`로 차례로 실행됩니다. 각 작업은 최대5시간30분이며 새 실행기에 상태를 내려받고 DB 무결성을 확인한 뒤 시작합니다. 행렬 번호 순서는 필요하지 않으며 동시에 하나만 실행되는 것이 조건입니다.

한 세션이 정상 한도 종료하면 다음 세션은 새 cron 이벤트를 기다리지 않습니다. 두 작업의 총 실행 예산11시간은 기존 거래소 운영 창(개장3시간30분 전~폐장30분 후, 정상장10시간30분)을 덮습니다. 운영 창 밖·휴장일이면 각 세션은 즉시 종료하므로11시간 동안 무조건 실행하지 않습니다. 검증 실패 시 세션을 시작하지 않으며, 세션 실패 시 fail-fast로 나머지를 취소합니다. 실패한 저장을 무시하고 다음 작업으로 진행하지 않습니다.

수동 실행은 기본1회 검사이며 `continue_session` 선택 시 같은 두 세션을 사용합니다. 비상 중단 요청은 반복 작업을 시작하지 않습니다. 원격 비상 중단 표시는 기존 세션의 대기 중 확인 규칙을 따르며 후속 작업도 상태를 새로 읽습니다. main 예약·배포는 동일 동시 실행 그룹을 유지합니다.

근거: [GitHub 공식 행렬·동시 실행·실패 처리 문서](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/run-job-variations),2026-10-17 확인. 실제 전날 연속 운영과 이번 직렬 설정 검증은 구분합니다. 다음 거래일의5시간30분 경계 인계는 아직 실장 관찰하지 않았습니다.

**남은 한계:** 최초 cron 지연·누락, 작업 사이 실행기 배정·설치 지연, 실행기 장애·강제 취소는 보장하지 않습니다. 작업 인계에도 짧은 공백이 생길 수 있으며15분 슬롯 검사가 이를 기록합니다. 정시 기동이 필수라면 상시 실행 환경 또는 외부 기동기가 필요합니다.
