# 공정 비교와 주문 복구

승인 설계: 동일 종목·구간·초기 자금의 비용 제외/포함 결과와 100% 단순 보유, 평균 투자 비중을 맞춘 단순 보유를 비교한다. 주문 상태·중복 방지·재시작 대조·손실 한도·비상 중단은 모의 증권사로 검증한다.

## 공정 비교

`intraday-state/종목/comparison.json`과 결과 페이지에 표시한다. 고정 후보의 앞 75% 개발 구간과 뒤 25% 보류 구간을 각각 계산하며 자동 우승 전략을 선정하지 않는다. 이전 완료 봉 신호로 다음 봉 시가에 재조정하며, 동일 초기 자본 1, 현금 이자 0, 종료 시 청산 비용을 포함한다. 수수료·슬리피지·반 스프레드 합계 편도 0.21%를 적용한다.

단순 보유는 최초 한 번 매수하고 끝까지 보유한다. 평균 노출 비교는 현금과 보유분의 최초 배분을 수치적으로 찾으며, 가격 변화로 변하는 실제 투자 비중의 시간 평균을 전략과 일치시킨다. 이는 **사후 설명용**이며 미래에 사용할 매매 신호가 아니다. 배당·차입·세금·체결량 제한은 반영하지 않는다. v2 부분 체결과 위험 중단 계좌의 실제 성과와 별도로 표시한다.

`cost_drag`: 비용으로 줄어든 수익률. `drawdown_reduction_from_cash`: 100% 보유 낙폭−같은 평균 노출 보유 낙폭. `drawdown_reduction_beyond_cash`: 같은 평균 노출 보유 낙폭−전략 낙폭. 음수는 악화다. 낙폭 차이는 설명용이며 현금의 인과 효과나 통계적 유의성을 입증하지 않는다. 비용·낙폭 지표에 따라 전략을 자동 선택하지 않는다.

## 주문 구조

`orders.py`는 단일 종목·단일 통제 계좌용 SQLite 컨트롤러와 별도 SQLite 모의 증권사를 제공한다. 실제 증권사 어댑터와 API 키는 없다.

신호 식별자를 주문 ID로 만들고 요청 내용을 영속 저장한 뒤 제출한다. 상태는 created → submitting → accepted → partial → filled/canceled/rejected다. 통신 실패는 unknown으로 기록하고 신규 주문을 차단한다. 재시작 시 같은 ID를 조회해 체결 수량과 잔고를 대조한다. 조회 결과가 없거나 내용·잔고가 다르면 중단한다. 제출 여부 불명인 주문은 자동 재전송하지 않는다. 동일 ID의 다른 주문 내용도 거부한다. 미해결 주문이 있는 동안 새 주문을 허용하지 않는다. 외부 수동 거래·입출금은 불일치로 판단하므로 별도 승인된 조정 절차가 필요하다. 다중 프로세스/실계좌 연결 전에는 독점 실행, 계좌별 원장, 공식 API의 멱등성 보장을 별도로 구현·검증해야 한다.

모의 증권사는 접수 후 응답 유실, 부분 체결, 취소 실패를 주입할 수 있다. `Controller.emergency_stop()`은 먼저 신규 주문을 차단하고 모든 비종료 주문의 취소를 요청하며 취소 확인 여부를 반환한다. 취소 통신 실패 시 계속 중단한다. 보유 자산을 자동으로 청산하지 않는다. 중단 후 자동 재개하지 않는다.

## 운영 v2 손실 제한·비상 중단

v2 모의 계좌는 일중 평가 손실 3%, 기록한 최고 평가액 대비 낙폭 10%에서 신규 매매를 중단한다. 일중 기준은 뉴욕 날짜별 첫 새 봉을 처리하기 전 계좌 평가액이다. 시가/종가에서 점검한다. 새 가격이 없는 동안 실시간 위험 감시를 하지 못하며, 급변·갭으로 한도를 넘는 손실이 가능하다. 중단 상태는 지속되고 보유분은 계속 평가한다. v1 비교용 기존 계좌는 원래 규칙을 유지한다.

GitHub → Actions → Intraday 15-minute paper research → Run workflow → emergency_stop 체크 → 실행하면 v2 전역 중단 파일을 저장한다. GitHub 실행 대기·장애로 즉시 중단이 보장되지 않는다. v2 주문은 봉 안에서 잔량을 만료시키므로 외부 미체결 주문이 없다. 이 운영 기능과 모의 증권사 주문 취소 복구 시험은 별도 구조다. 실계좌 기능 완성으로 해석하지 않는다.

검증: 노출 일치, 비용 영향, 현금/100% 보유, 미래 구간 비참조, 응답 유실 후 재시작·중복 방지, 부분 체결·취소, 취소 실패, 잔고 불일치, ID 충돌, 손실 한도, v2 중단.
